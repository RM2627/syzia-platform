CORREÇÃO PÓS-HOMOLOGAÇÃO — VIRELOQ 030
CATEGORIAS + IDENTIDADE VISUAL + CATÁLOGO + PORTFÓLIO + PUBLICAÇÃO

IMPORTANTE:

Esta tarefa parte EXCLUSIVAMENTE da versão consolidada 030 já entregue.

Ela NÃO é uma nova auditoria completa da VIRELOQ.

Durante a homologação real com a MS Auto Details foram identificados
problemas de experiência de uso na configuração dos serviços e da
presença pública da empresa.

O objetivo desta tarefa é corrigir SOMENTE os pontos descritos abaixo.

==================================================
1. LIMITES DA TAREFA
==================================================

NÃO:

- refazer a implementação 030;
- reconstruir módulos não relacionados;
- alterar migrations 001–030;
- criar migration 031 sem necessidade comprovada;
- resetar banco;
- modificar RLS sem necessidade;
- alterar autenticação;
- alterar Financeiro;
- alterar Métricas;
- alterar trial;
- alterar billing;
- alterar primeiro acesso;
- alterar CPF/CNPJ;
- alterar suporte autorizado;
- alterar regras de atendimento;
- alterar funcionalidades não relacionadas;
- fazer deploy;
- acessar Supabase real.

ANTES de criar qualquer alteração de banco:

1. inspecione a implementação 030;
2. verifique se o schema/RPC/backend atual já suporta a operação;
3. reutilize a infraestrutura existente.

Estas correções parecem predominantemente de UX/frontend e integração
com recursos já existentes.

==================================================
2. TESTES — IMPORTANTE
==================================================

NÃO repetir a auditoria mestre completa nem executar uma bateria
desnecessariamente extensa de testes.

O proprietário fará a homologação funcional posteriormente.

Executar somente os testes ESSENCIAIS para garantir que estas correções
não quebraram o fluxo diretamente afetado.

Obrigatório:

- build;
- typecheck, se separado;
- testes diretamente relacionados às alterações;
- teste básico de isolamento entre empresas nas operações alteradas;
- uma jornada curta no navegador cobrindo os fluxos corrigidos.

Não gastar grande parte da tarefa reexecutando centenas de testes de
módulos que não foram alterados.

Se alguma alteração tocar inesperadamente uma camada sensível, executar
os testes adicionais estritamente necessários para aquela camada.

Documentar exatamente o que foi testado.

==================================================
3. PROBLEMA 1 — CATEGORIA NO CADASTRO DE SERVIÇO
==================================================

A implementação 030 já possui categorias persistentes por organização.

Na homologação foi confirmado que as categorias existentes aparecem
corretamente no select.

Exemplo real da MS Auto Details:

- Higienização automotiva;
- Higienização de estofados;
- Lavagem automotiva.

Portanto, a reutilização funciona.

O problema é:

NO FORMULÁRIO DE NOVO SERVIÇO NÃO EXISTE UMA FORMA CLARA DE CRIAR UMA
NOVA CATEGORIA.

Hoje o usuário encontra apenas um select contendo:

- Sem categoria;
- categorias existentes.

Isso não cumpre completamente a experiência aprovada.

==================================================
4. NOVO COMPORTAMENTO DA CATEGORIA
==================================================

No cadastro e edição de serviço, permitir:

A) selecionar categoria existente;

OU

B) criar uma nova categoria sem sair do formulário.

Experiência sugerida:

Categoria

[ Selecione uma categoria ]

- Sem categoria
- Higienização automotiva
- Higienização de estofados
- Lavagem automotiva
----------------------------
+ Criar nova categoria

Ao selecionar:

+ Criar nova categoria

mostrar:

Nome da categoria
[________________]

[ Criar categoria ]

Depois de criar:

1. persistir na organização atual;
2. selecionar automaticamente a categoria no serviço atual;
3. disponibilizá-la imediatamente nos próximos serviços.

Se a infraestrutura existente permitir um combobox pesquisável com:

Criar “Polimento”

também é aceitável.

Priorizar clareza.

==================================================
5. NÃO DUPLICAR CATEGORIAS
==================================================

Preservar as regras da 030:

- categoria pertence à organização;
- reutilização;
- renomeação;
- ordenação;
- desativação;
- exclusão segura;
- isolamento multiempresa.

Não criar um segundo sistema de categorias.

==================================================
6. EXPERIÊNCIA DO CONSUMIDOR — PROBLEMA ATUAL
==================================================

Durante a configuração real da MS Auto Details, a área atual de
“Experiência do consumidor” mostrou-se confusa.

Atualmente estão misturados na mesma experiência:

- publicação;
- upload genérico de imagem empresarial;
- logo;
- capa;
- cor;
- ordem de categorias;
- ordem dos serviços;
- portfólio;
- preparação futura de pagamentos;
- solicitações.

O proprietário, mesmo conhecendo o produto, teve dificuldade para
entender como adicionar as fotos de cada trabalho.

Portanto, reorganizar essa experiência.

==================================================
7. OBJETIVO DA NOVA EXPERIÊNCIA
==================================================

Um novo cliente deve conseguir, sem treinamento prévio:

1. adicionar logo;
2. adicionar capa;
3. escolher a cor da marca;
4. organizar categorias;
5. organizar serviços;
6. adicionar imagem a um serviço;
7. cadastrar trabalho no portfólio;
8. adicionar fotos desse trabalho;
9. visualizar como o consumidor verá;
10. publicar.

A interface deve explicar isso sozinha.
